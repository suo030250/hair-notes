# Hair Notes 每日編輯計畫

目標：每天新增一篇給客人閱讀的繁體中文文章。排程為台北時間上午 09:00，附加於目前聊天；執行狀態由 App 排程管理，進度由 [daily-state.json](daily-state.json) 記錄。

## 四支柱輪播

| --- | --- | --- | --- |

以上題目是待研究問題，不是預先定論。沿用既有分類，不改寫網站分類程式；以 tags 加入支柱中文名稱。第一輪依上述順序，成功發布一篇後才移至下一支柱。已發布日期與文章 ID 不能重複。

## 每次執行

1. 先讀根目錄 AGENTS.md、Wiki 索引與日誌；檢查本機修改及當天（Asia/Taipei）是否已完成。
2. 若 pending 不為 null，先恢復該文章的查核、檢查或發布；不要另開新文章累積重複草稿。
3. 依 next_pillar 選題，核對作者、年份、正式篇名、DOI、文獻類型及能讀到的範圍。使用者提供的 [候選書目](../../raw/reference/daily-pillars-2026-11-10.md) 尚未核實，不能只根據標題寫結論。原始全文不可取得時記錄限制，優先另找可讀取的原始研究或專業機構資料。
4. 主張至少有一份直接支持該主張的可靠來源；醫療與營養議題另以現行專業機構資料或適切綜述交叉查核。不是每篇強求多份原始研究；同一研究的轉述不算獨立證據。
5. 先保存 raw 原始資料或可讀取快照及取得資訊，再建立來源摘要與相關 Wiki，更新 index、日誌、公開 JSON。正文以客人問題、白話解釋、適用範圍及可帶去諮詢的問題組成，篇幅以能說清楚一題為準。
6. 對落髮僅提供症狀觀察與就醫溝通，不做診斷或處方；對成分與營養區分機轉、體外、動物與人體結果，保留對照、樣本、利益關係與限制。不宣稱缺乏證據的生髮療效，不提供補充劑劑量或取代個別醫療評估。
7. 執行 `python tools/check_site.py`、`node --check docs/assets/js/app.js`；確認原始來源未被改寫、文章 ID 唯一、引用有效、正文與來源相符。新增內容沿用現有樣式，必要時實測閱讀頁。
8. 使用已授權的 GitHub 連線或正確帳號的 git，提交明確相關檔案至 suo030250/hair-notes。排除 raw 全文、個資與暫存；不得強制推送或覆蓋使用者未提交修改。不以其他帳號推送，也不新增憑證或擴張權限來繞過登入問題。
9. 驗證公開網站的 JSON 包含新文章 ID，且文章頁能顯示其內容，才將當日記為完成。history 記錄日期、支柱、ID、網址與 commit（可取得時）；更新 last_published_date、last_article_id、last_article_url，清空 pending，推進 next_pillar。檢查先前遠端是否已有文章，避免發布成功但記錄失敗造成隔天重複。
10. 發布成功時通知標題、支柱、來源與網址；失敗時保留 pending（包含 date、pillar、article_id、stage、reason），通知具體阻礙，不宣稱已上線。當日已完成或狀態未變時保持安靜。未發布不推進支柱，不在隔日一次補發多篇。

## 執行條件

本排程需要本機專案、網路與可寫入的 GitHub 存取；保持電腦開機、桌面 App 執行。排程建立不代表發布管道已自動通過驗證；前次 GitHub 上傳曾使用互動式網頁流程，無人值守執行若無可用寫入授權，必須保留草稿並回報，不能視為已發布。
